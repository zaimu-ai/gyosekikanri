# 給与システムとの統合に向けたメモ（案）

作成：2026-11-19。請求システムと勤怠給与システムを、あとで一緒に使えるようにするための考え方です。まだ何も統合していません。

## 1. 事務コンの形

事務コンのメインメニューは「売上管理」と「給与管理」の2つでした。担当の方にとっては、ひとつの業務システムです。

統合後も、最初の画面でこの2つを選ぶ形にすると、迷いにくくなります。

- 売上管理：日次業務、締日業務、登録業務、年次業務
- 給与管理

## 2. 今、合わせてあること

- どちらも、1つの HTML ファイルで動き、ブラウザの中に保存します。
- 保存先の名前は別々です。そのため、同じブラウザで両方を開いても、データはまざりません。
  - 請求システム：IndexedDB の database `seikyu-system`
  - 給与システム：別の database
- 同じデザインのきまりを使っています。
  - 設計書 第12版「10. デザインの決まり」
  - 44px、14px、ラベルの位置、エラーの出し方、Lucide、左端の帯なし、ダークモード
- テストデータと本番のデータを分けています。
- 取消は記録を残します。変更の前には端末内バックアップを取ります。

## 3. 統合するときの案

| 項目 | 案 |
|---|---|
| 入口 | 「売上管理／給与管理」を選ぶ入口のページを1つ作り、そこから各システムを開く。いきなり1つのファイルにまとめない |
| 会社の情報 | 会社名・住所・登録番号・振込先は、共通の「会社」データとして1か所で持つ。今は請求システムの `S.company` にある |
| 保存先 | 今のまま、システムごとに別の database にする。共通のものだけ別の key（例：`company`）に置く |
| バックアップ | 両方のデータをまとめて書き出せるようにする。中身はシステムごとに分ける |
| 運用先 | 1台のパソコンか、複数の人・複数のパソコンで共有するか（確認事項 S12）。両方のシステムで同じ結論にする。共有するなら、サーバーかクラウドの保存先が必要 |
| 担当者・権限 | 給与のデータは見られる人を限る必要がある。共有するなら、ログインと権限を一緒に設計する |

## 4. 統合の前に決めること

1. 運用先：1台か、共有か。
2. 給与システムの今の保存の形と key の名前。両方を並べて、ぶつからないか確かめる。
3. デザインの仕上げ（Codex）を、両方のシステムで同じ部品（CSS 変数・ボタン・表）にそろえるか。
