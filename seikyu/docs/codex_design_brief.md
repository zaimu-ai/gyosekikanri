# Codex へのデザイン依頼書：請求システム v0.3.0

作成：2026-11-19（Claude Code）。この依頼書は、画面の**見た目（デザイン）だけ**を Codex に仕上げてもらうためのものです。

## 1. お願いしたいこと

担当の方は長く事務コン（旧システム）を使ってきました。**入力の順番と項目は事務コンに合わせ済み**です。これを崩さずに、見やすく・間違えにくく・速く入れられる見た目に仕上げてください。

優先する順に並べます。

1. **納品書の入力**（`#delivery-new`）：PC では、事務コンの「自社納品書発行」画面と同じように、1行1明細の表として見えるようにする。
   - 上段：日付／得意先コード／得意先名／伝票No.
   - 明細の列：商品名／単位重量／本数／重量／単価（K）／金額／摘要／摘要
   - 明細の下：寸法の行（外径／種類（内径か肉厚）／内径・肉厚／長さ／ケース）
   - 下：ケース合計／重量計／合計金額
   - スマホでは、今のカード形式のままでよいです。
2. **製作伝票入力**（`#order-new`）：紙の製作伝票と同じ並びにする。
   - 伝票No.・日付・納期 → 得意先・ユーザー・送り先・注文番号 → 商品名・寸法 → 受注量・単価（P/K）・出荷の注意
   - 1枚入れたら次の1枚、と続けて入れる流れが速くなるようにする。
3. **得意先の取込**（`#customers-import`）：確認の表を読みやすくする。取り込む／取り込まない／取り込めない、の区別と理由が一目でわかるようにする。
4. **宛名ラベル**（`#labels`・`#addressee-new`）：宛名を選ぶ表と用紙の設定を、迷わず使えるようにする。ラベルそのもの（`.label-page`・`.lb`）の位置と大きさは mm で決めているので変えない（文字の太さ・行の間隔は相談のうえで可）。
5. そのほかの画面（ホーム・一覧・請求書・入金・台帳・設定）の調子をそろえる。

### 事務コンの画面（参考）

担当の方が見慣れている画面です（画面写真には実在の取引先が写っているため、repository には入れていません。下の説明を手がかりにしてください）。

- 自社納品書発行：上段に日付・得意先、中段に明細の表、下段に寸法の表。
- 仮納品書発行：送り先コード・送り先名、明細に「注文番号」の列。
- キーの案内：品名を入れて（実行）、仮納品書呼出（F1）、製品伝票呼出（F2）、前品名コピー（F3）、挿入（F4）、削除（F5）、終了。
  - このシステムでは、Enter（実行）で得意先コードを決められます。
  - 「前の行をコピーして足す（前品名コピー）」ボタンがあります。
  - ファンクションキーの割り当ては任意です。付ける場合は、画面に案内を出してください。

実在の会社名・取引先名・口座番号を、コード・テストデータ・コメント・commit message に書かないでください（この repository は公開です）。

## 2. 変えてよいもの・変えないもの

| 変えてよい | 変えない |
|---|---|
| `src/00-head.html` の CSS（色・余白・文字の大きさ・並べ方） | 計算（`src/20-core.js`）、保存のしくみ・保存の形（`DATA_VERSION`・IndexedDB の key） |
| 各画面の HTML の組み立て（`src/30-views.js`・`src/35-delivery.js` などの中の、class・要素の並び・見出し） | 要素の `id`、`data-act`・`data-l`・`data-s`・`data-f`・`data-di`・`data-df` 属性（テストと動きがこれを使います） |
| アイコンの選び方（Lucide 0.460.0 の中から） | 画面の文言の**意味**（言い回しを短くするのはよいが、「取消」「締日なし」など業務の言葉は変えない） |
| | 外部ライブラリの版（Lucide 0.460.0・Noto Sans JP・html2canvas 1.4.1・jsPDF 2.5.1） |
| | 帳票（`src/40-print.js`）の大きさ・ページ分け、宛名ラベルの位置と大きさ（`src/45-labels.js` の mm の計算）。A4 の印刷位置が変わるため、変えたいときは相談 |

## 3. 守るきまり（必ず）

- デジタル庁デザインシステム、Apple Human Interface Guidelines、Material Design 3 を参考にする。
- アイコンは Lucide。**絵文字は使わない**。
- **カードや通知の左端にだけ色の帯を付ける表現は使わない**（`border-left` も、疑似要素・`inset` の影で同じ見た目を作るのも不可）。
- 色は `:root` の CSS 変数で決め、ダークモード（`prefers-color-scheme` と `data-theme`）にも対応する。状態は色だけで伝えず、アイコンと文字も付ける。
- 押せる部分は高さ 44px 以上。文字は 14px 以上（表の補足は 13px まで）。
- ラベルは入力欄の上。「※必須」「※任意」を付ける。エラーは入力欄の下に「＊」で始め、直し方を書く。
- 同じ行の入力欄の上端をそろえる（v0.3.2 で利用者の依頼により入れました。`.field-hd`・`.field-ctl` と subgrid のしくみ）。入力欄の高さの設定（`--ctl-h`・`--ctl-py`・`--seg-h`、`:root[data-fieldh]`。「ふつう」「低め」「さらに低め」）も残す。
- スマホ幅（390px）で横にはみ出さない。PC（1366px）で、納品書の明細が横に1行で見える。
- 未入力・計算できない値は「—」で表示し、0 と見分けられるようにする。
- 登録したデータを消す・空で上書きする処理を書かない（見た目の仕事では触らないはずですが、念のため）。

## 4. 確かめかた

1. `bash build.sh` で `dist/` を作る。
2. `dist` で `python3 -m http.server 8766` を動かす。
3. 文字コードを UTF-8 にして（`LANG=C.UTF-8`）、次をすべて実行し、NG が 0 件であることを確かめる。
   - `node tests/calc.test.cjs`
   - `node tests/e2e.cjs`
   - `node tests/e2e2.cjs`
   - `node tests/e2e3.cjs`
   - `node tests/e2e4.cjs`
   - `node tests/e2e5.cjs`
   - `node tests/e2e6.cjs`
   - `node tests/pages.cjs`
   - `node tests/file-mode.cjs`
4. 次の画面の画面写真を、1366px と 390px、明るい表示と暗い表示のそれぞれで撮って、出来上がりとして渡す。
   - ホーム、製作伝票入力、納品書の入力、請求書、得意先の取込、宛名ラベル
5. 確かめていないことを「確かめた」と書かない。
