# 請求システム（アルミ引抜管メーカー向け）試作 v0.3.0

更新日：2026-11-19　状態：試作（テストデータで確認済み。本番の運用はまだ）

事務コンで行っている「製作伝票 → 納品書 → 合計請求書」の流れを、ブラウザで動く1つのファイルにしたものです。
参照した資料：旧システム（事務コン）の画面・帳票と業務の聞き取り。実物には実在の取引先が載っているため、この repository には入れていません（利用者の Google ドライブにあります）。

## 0. 第3版（v0.3.0）で変えたこと

| 変えたこと | 中身 |
|---|---|
| 宛名ラベル（新しいタブ） | 仕入先などの封筒に貼るラベルシールを、A4 のラベル用紙に印刷します（PDF でも保存できます）。宛名は得意先とは別に登録し、請求書は作りません。得意先のラベルも選べます |
| ラベルの用紙 | 12面・10面・18面・24面と「自分で決める」（列・段・ラベルの寸法・余白・間隔を mm で入れる）。使いかけの用紙のために「何枚目から使うか」、1件あたりの枚数、敬称（御中・様・殿・なし）、印刷のずれの調整（右へ・下へ mm）を選べます |
| 住所が空欄の宛名 | ラベルに印刷できないため選べないようにし、理由を出します（黙って外しません） |
| 取込 | 締日 0 の行（仕入先など）は、得意先ではなく宛名に取り込みます。締日が空欄の行は理由を出して取り込みません |
| 保存の形 | 第3版（DATA_VERSION 3）。宛名とラベルの設定を足しました。第1版・第2版のデータはそのまま読めます |

## 0-2. 第2版（v0.2.0）で変えたこと

| 変えたこと | 中身 |
|---|---|
| 「指図書」を「製作伝票入力」に | メニュー・画面・帳票の言葉をすべて「製作伝票」にしました。入力の順番を紙の製作伝票に合わせました（製作伝票No.・日付・納期 → 得意先・ユーザー・送り先・注文番号 → 商品名・寸法 → 受注量・単価（P／K）・出荷の注意）。登録すると、続けて次の伝票を入れられる空の画面に戻ります |
| 得意先コードで入れる | 製作伝票・納品書の得意先は、事務コンと同じくコードを入れて Enter で選べます（名前から選ぶこともできます）。ないコードは知らせます |
| 摘要を事務コンと同じ形に | 製作伝票から納品書を作ると、摘要＝「ユーザー 製作伝票の日付 受注量」（例：見本台 10/27 5M）、摘要2＝「製作伝票No. 送り先の略称＋入」または「製作伝票No. 出荷日＋出」（例：30110001 11/5出）を自動で入れます。送り先・納品日を変えると摘要2も入れ直します（手で直した摘要はそのまま） |
| 納品書の入力 | 「前の行をコピーして足す（前品名コピー）」、明細ごとの「注文番号」を足しました。製作伝票の単価が P（円/本）なら納品書も円/本になります |
| 得意先の取込 | 「得意先」→「得意先を取り込む（CSV）」。全部の行を確かめる画面を出してから取り込みます。読めない行は理由を出して取り込みません。同じコードの得意先は上書きしません。取り込む前に端末内バックアップを取ります。文字コードは UTF-8・Shift_JIS のどちらでも読みます |
| 請求先（事務コンの「請コード」） | 支店・工場などの売上を、本社などの別の得意先の請求書にまとめられます（得意先の画面の「請求先」）。まとめる側の請求書・得意先台帳・未入金額に入ります |
| 得意先ごとの消費税の円未満（事務コンの「丸目」） | 得意先ごとに 切り捨て／四捨五入／切り上げ を選べます（空なら会社の設定）。請求一覧表で、丸目 0＝切り捨て、1＝四捨五入 を確かめました |
| 締日なし | 宛名だけの登録（役所・銀行など）のため、「締日なし（請求書を作らない）」を選べます。締日なしの得意先に、まだ請求していない納品書があるときは、請求書の画面で知らせます（黙って外しません） |
| 得意先の項目 | メニュー（読みの頭文字）・住所2・FAX番号、取り込んだときに空欄にした項目（文字が重なって読めなかった項目）の表示、事務コンの元の値（参考）。送り先にコードと略称 |
| 保存の形 | 第2版（DATA_VERSION 2）。第1版のデータはそのまま読めます（足した項目は「未設定」で補い、ほかは変えません） |

画面の見た目（デザイン）の仕上げは Codex が担当します（`docs/codex_design_brief.md`）。この版では、入力の順番と項目を事務コンに合わせることを優先し、見た目は最低限にしています。

## 1. 業務の流れと画面

| 順番 | 今（事務コン） | このシステム |
|:-:|---|---|
| 1 | 製作伝票が届く（出荷決定） | 「製作伝票入力」に登録する（しなくてもよい） |
| 2 | 自社納品書発行・仮納品書発行の画面に手で入力 | 「納品書を入力する」。製作伝票から呼び出せる。寸法と本数から重量を計算。はかった重さを入れればそれを使う。単価は製作伝票の単価か、同じ得意先・材質・寸法の前回の単価が入る |
| 3 | 仮伝票（3枚綴り）・納品書（4枚綴り）を印刷 | 1件の納品書から、納品書・納品書（控）・受領書、仮納品書・仮納品書（控）・受領書を A4 に印刷（2枚分を上下に並べる）。PDF でも保存できる。事務コンのように仮納品書と自社納品書を別々に入れ直す必要はありません |
| 4 | 得意先台帳を出して請求明細と照合 | 「得意先台帳」で売上・消費税・入金・差引残高を見る・印刷する |
| 5 | 合計請求書を発行・郵送 | 「請求書」で締め日を選び、得意先ごとに作る（請求先にまとめる得意先の分も入る） |
| 6 | 入金入力処理 | 「入金」に登録（振込手数料などの差し引きも）。次の請求書の入金額に入る |

画面：ホーム／製作伝票入力／納品書／請求書／入金／得意先台帳／得意先（取込を含む）／宛名ラベル／設定・データ

## 2. 使い方（置き場所）

| 使い方 | 開き方 | 印刷 | データの保存先 |
|---|---|---|---|
| 本番で使う（おすすめ） | `請求システム.html` を事務所のパソコンに置き、Chrome か Edge で開く（ダブルクリック） | できる（A4・縦・余白なし・倍率100%） | そのパソコンのブラウザの中 |
| 試す・見る | claude.ai の非公開ページ | できない（PDF で保存して印刷） | 見ている人のブラウザの中（ページごとに別） |

- 最初はテストデータ（架空の取引先・架空の会社）で開きます。「設定・データ」→「本番のデータに切り替える」で、空の本番データに切り替わります。テストデータと本番のデータは別々に保存され、切り替えても消えません。
- 得意先を取り込むときは、先に本番のデータに切り替えてください（テストデータに取り込んでも本番には入りません）。
- データはそのブラウザの中だけにあります。ほかのパソコン・ほかのブラウザとは共有されません。

## 3. 計算のきまり（実物の帳票で確かめた値）

| 項目 | このシステムの計算 | 確かめた資料 |
|---|---|---|
| 1mの重さ | （外径−肉厚）×肉厚×0.0085（kg）、小数5桁で四捨五入。内径で入れたときは肉厚＝（外径−内径）÷2 | 製作伝票 18×11 の M単重 0.43138 |
| 1本の重さ | 1mの重さ×長さ÷1000、小数2桁で四捨五入（0.1kg 未満の小さい部品は5桁） | 事務コンの画面 82.00×68.50×2,337.6 → 10.09 |
| 計算重量 | 1本の重さ×本数を足して、小数1桁で四捨五入 | 事務コンの画面 10.09×42本 → 423.8 |
| 請求に使う重量 | はかった重さを入れればそれ、空なら計算重量 | 納品書の見本は 417.9（はかった重さ） |
| 金額 | 重量×単価（K）か本数×単価（P）、円未満切り捨て | 納品書の見本 12.2kg×1,299＝15,847.8 → 15,847 |
| 消費税 | 請求書ごとに 税抜の合計×10%。円未満は得意先の設定（丸目）、なければ会社の設定（四捨五入） | 請求一覧表：丸目1 の 109,640.8→109,641（上げ）と 236,907.4→236,907（下げ）で四捨五入、丸目0 の 146,385.9→146,385 で切り捨て |
| 繰越額 | 前回請求額−入金額（振込手数料などを含む） | 合計請求書の「当月繰越残高」 |
| 今回請求額 | 繰越額＋今回の売上（税抜）＋消費税 | 同上 |

- 締め日：得意先ごとに 5・10・15・20・25日・末日・その他（1〜28日）・締日なし。
- 締め日までの、まだ請求していない納品書と入金を、すべてその請求書に入れる（請求先にまとめる得意先の分も）。
- 単価・重量が入っていない納品書があると、その請求書は作れない（0円として計算しない）。

## 4. データを守るしくみ

- 登録したデータを消す機能はありません。納品書・請求書・入金・製作伝票は「取消」（理由を必ず記録）、得意先は「取引停止」、送り先は「使わない」で表します。
- 請求書に入った納品書・入金は直せません。直すときは請求書を取り消します（新しい請求書から順に）。
- 請求書を作る前・取り消す前・設定を変える前・データを戻す前・得意先を取り込む前と、毎日の最初の保存のときに、端末の中に自動バックアップ（最新20件）を取ります。
- 「バックアップを書き出す」で全データを1つのファイル（.json）に保存できます。
- 保存されているデータが読めないときは、何も保存せず、保存されている内容をそのまま書き出す画面を出します。

## 5. 事務コンから移るときの手順（案）

1. 「設定・データ」で本番のデータに切り替え、会社の情報と振込先を確かめる。
2. 伝票の番号に、事務コンで最後に使った番号の次を入れる（納品書No.・仮納品書No.・請求書No.）。
3. 「得意先」→「得意先・宛名を取り込む（CSV）」で、得意先一覧の CSV（別にお渡ししたもの）を取り込む。締日がある行は得意先に、締日 0 の行（仕入先など）は宛名ラベル用の宛名に入ります。
4. 得意先の一覧で「空欄の項目がある得意先」を表示し、空欄の住所・電話番号を手で入れる。
5. 請求する得意先ごとに「開始時の残高」（移る直前の締め日と、その請求書の今回請求額）を入れる。
6. しばらくは事務コンと並べて使い、請求書の額が一致するか確かめる。

## 6. デザイン

デジタル庁デザインシステム、Apple Human Interface Guidelines、Material Design 3 を参照。押せる部分は高さ44px以上、文字は14px以上、ラベルは入力欄の上に「※必須」「※任意」、エラーは入力欄の下に「＊」で始めて直し方を書く、アイコンは Lucide、左端の色の帯は使わない、状態は文字とアイコンでも示す、ダークモード対応、スマホ幅（390px）で横にはみ出さない。
見た目の仕上げは Codex に任せます（依頼書：`docs/codex_design_brief.md`）。
